## 2. Step-by-step plan

### Step 2.1 — Pre-cache (parallel, can start while drafting presets)

```powershell
# Base model (verify if already cached first via `hf-fm status Qwen/Qwen3-0.6B-Base`)
hf-fm Qwen/Qwen3-0.6B-Base --timeout-per-file-secs 1800

# Production CLT
hf-fm bluelightai/clt-qwen3-0.6b-base-20k --timeout-per-file-secs 1800

# Bonus dev 16K
hf-fm bluelightai-dev/clt-Qwen3-0.6B-Base-16k-test --timeout-per-file-secs 1800
```

The `--timeout-per-file-secs 1800` flag is the documented workaround for the
`hf-fm` per-file wall-clock-deadline that trips on slow connections (default
300s would timeout the 1-2 GiB W_dec files at ~5 MiB/s).

`vocab_scan` creates the output's parent directory automatically via
`fs::create_dir_all`; no manual `mkdir` step needed.

    --model Qwen/Qwen3-0.6B-Base `

### Step 2.4 — Rhyme-group selection criteria

For each size, read the clean JSON's `rhyme_group_counts` and identify:

**Good candidates** (diverse content English words, not just BPE noise):
- `EY1 SH AH0 N` (-ation): rich morphological family (celebration, preparation, expectation, …)
- `IY1 N` (-teen): tight numeric family (thirteen, fifteen, …)
- `EH1 L F` (-self): the 6 reflexive pronouns
- `UH1 D` (-ould): modal verbs (could, should, would)
- `AE1 T` (-at): English -at words (at, mat, rat, …) — plan's original target

**Skip** clusters whose top-K is dominated by:
- 2-letter pinyin syllables (ki, qi, xi, ja, ko, …) — `IY1`, `AA1`, `OW1`, `AY1` are largely this
- Short transliterations or initialisms

Pick **2-3 rhyme groups per size** with diverse sample-words for sweeps.

### Step 2.5 — Populate presets

Edit `examples/figure13_planning_poems.rs`.  Per (size, rhyme-group) pairing, add
a `Preset` const.  Update `select_preset` to dispatch each new preset name.

**Preset naming convention**: `qwen3-{size}-{width}-{rime-tag}`
- `qwen3-1.7b-20k-ation`
- `qwen3-1.7b-20k-teen`
- `qwen3-0.6b-20k-ation`
- `qwen3-0.6b-16k-ation`
- … etc

**Preset template** (per pairing):

```rust
const QWEN3_1_7B_ATION: Preset = Preset {
    model: "Qwen/Qwen3-1.7B-Base",
    clt_repo: "bluelightai/clt-qwen3-1.7b-base-20k",
    prompt: "At every grand celebration,\n\
             Each careful preparation,\n\
             Brings joy beyond expectation,\n\
             And then the brief",
    suppress_word: "duration",   // (or another natural -ation word; check vocab top-1)
    inject_word: "myself",       // (from -self cluster, contrasting rime)
    suppress_features: &[
        (L, idx),  // pick top-3 features from the -ation cluster in clean JSON,
        (L, idx),  // sorted by `max_cosine` descending and with the prompt's
        (L, idx),  // rhyme words in the top-K
    ],
    inject_feature: (L, idx),    // top -self feature
    strength: 10.0,
};
```

**How to pick `suppress_features` / `inject_feature`**: open the clean JSON,
filter by `cmudict_rime == "EY1 SH AH0 N"`, sort by `max_cosine` descending,
take the top 2-3.  For the inject, do the same for the contrasting rime.

**`select_preset` dispatch addition**:

```rust
"qwen3-1.7b-20k-ation" => Ok(&QWEN3_1_7B_ATION),
"qwen3-1.7b-20k-teen"  => Ok(&QWEN3_1_7B_TEEN),
"qwen3-0.6b-20k-ation" => Ok(&QWEN3_0_6B_ATION),
// ...
```

Remove or repurpose the original `QWEN3` placeholder + its placeholder check
(the new explicit presets supersede it).

### Step 2.8 — Release v0.1.11

Per [docs/roadmaps/release-sequence.md](roadmaps/release-sequence.md) (consult before running):

```powershell
# 1. Pick up the latest hf-fetch-model patch (per CLAUDE.md Pre-commit Checks)
cargo update -p hf-fetch-model

# 2. Bump Cargo.toml line 3: version = "0.1.10" → "0.1.11" (edit manually)

# 3. Refresh Cargo.lock so it matches the bumped Cargo.toml.
#    Any cargo invocation does this; `cargo check` is the cheapest.
cargo check --features clt,sae,transformer

# 4. CHANGELOG.md: rename `[Unreleased]` to `[0.1.11] - 2026-05-27`, then
#    insert a fresh empty `[Unreleased]` section at the top with empty
#    `### Changed` / `### Fixed` / `### Added` sub-sections.

# 5. Commit Cargo.toml + Cargo.lock + CHANGELOG.md together (CRITICAL —
#    publish.yml fails on dirty Cargo.lock per memory).
git add Cargo.toml Cargo.lock CHANGELOG.md
git commit -m "chore: release 0.1.11"

# 6. Pre-commit gate (Windows-safe subset — skip `--all-features` because
#    of the metal/objc2 macOS-only dep; CI handles per-feature lanes).
cargo fmt --check
cargo clippy --features clt,sae,transformer --lib -- -D warnings
cargo clippy --features transformer --lib -- -W clippy::pedantic
cargo clippy --features rwkv --lib -- -W clippy::pedantic
cargo test --features clt,sae,transformer --lib
$env:RUSTDOCFLAGS="-D warnings"; cargo doc --features clt,sae,transformer --no-deps; $env:RUSTDOCFLAGS=$null

# 7. Push everything (including the 7 unpushed Wednesday handoff commits
#    plus today's new work), wait for CI green.
git push origin main
# Watch CI on GitHub. WAIT for green before next step.

# 8. Dry-run publish (always; per `feedback_dry_run_before_tag` memory).
cargo publish --dry-run

# 9. Tag (publish.yml fires on `v*` tags, excluding hyphenated ones).
git tag v0.1.11
git push origin v0.1.11

# 10. Monitor publish.yml on GitHub Actions; once green, v0.1.11 is live
#     on crates.io.
```

**CRITICAL** (per memory):
- Always commit `Cargo.lock` together with `Cargo.toml` — `publish.yml` fails on dirty Cargo.lock
- Tags `vMAJOR.MINOR.PATCH` only (`v0.1.11`); hyphenated tags (`v0.1.11-rc1`) do NOT publish
